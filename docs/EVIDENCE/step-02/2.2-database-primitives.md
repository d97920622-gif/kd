The four functions:

- `uuid_generate_v7()`: `EXTRACT(EPOCH FROM clock_timestamp()) * 1000` in the
  first 48 bits, the version nibble forced to 7, the RFC 4122 variant forced to
  `10`, the remaining 62 bits from `gen_random_bytes(10)`. `clock_timestamp()`
  rather than `now()` so two rows inserted in one transaction sort by insertion
  order instead of sharing a timestamp.
- `set_updated_at()`: `BEFORE UPDATE`, sets `NEW.updated_at := now()`. It does
  not touch `version`; optimistic locking is 2.12's owner and a hidden bump
  would let an update pass without its `WHERE version = ?`.
- `apply_universal_columns(table, scoped)`: idempotent `ADD COLUMN IF NOT
EXISTS` for the six columns, the primary key when there is none, the tenant
  index, and the `updated_at` trigger. `scoped = true` makes `company_id` NOT
  NULL.
- `assert_universal_columns(table)`: raises at apply time, naming what is
  missing, so a forgotten column fails the migration and not the step gate.

The 2.2 migration also upgrades the two 2.1 ledgers: `id` default becomes
`uuid_generate_v7()`, `version` starts at 0 as `MASTER_PROMPT.md` specifies,
and the business-key unique indexes become partial on `deleted_at IS NULL`.

## 5. The static check, each rule proved to fire

`check:schema-standards` reads migration text so `npm run verify` fails
without a database. Six probes were written into `migrations/`, run and
deleted:

```text
missing universal columns:
  table probe must declare the universal column id (uuid NOT NULL DEFAULT uuid_generate_v7())
  table probe must declare the universal column company_id (uuid)
  table probe must declare the universal column created_at (timestamptz NOT NULL DEFAULT now())

wrong types:
  table probe column created_at must be timestamptz NOT NULL DEFAULT now()
  a timestamp column must be timestamptz, never timestamp without time zone
  the column type double precision is forbidden; money is numeric(18,4)

foreign key without restrict:
  every foreign key must declare ON DELETE RESTRICT

bad index and constraint names:
  index wrong_idx on probe must be named idx_probe_{columns}
  constraint wrong_name must start with chk_

transaction in a migration:
  the runner owns the transaction; a migration must not open or close one
  the runner owns the transaction; a migration must not open or close one

numeric not 18,4:
  numeric(10,2) is not numeric(18,4)
```

Two implementation notes worth keeping:

- The first version scanned raw text, so the word `timestamp` inside a
  comment and inside `COMMENT ON ... IS '...'` produced three false
  positives in the 2.2 migration itself. The check now masks comments and
  string literals in place (each masked character becomes a space), so every
  offset still points at the original line.
- The catalog query first compared names with `LIKE 'idx\\_' || table || '\\_%'`,
  which matched the literal backslash and reported all twelve correctly named
  constraints and indexes as violations. It now uses `starts_with(...)`.

## 8. Boundaries

- **RLS** is still off on both ledgers. 2.7 owns the framework and enables it
  for every table in one place, together with `check:rls-coverage`.
- **Audit triggers** arrive in 2.8, which attaches them to every table.
- **`version` semantics** stay with 2.12 (optimistic locking); 2.2 only
  defines the column and its default.
- **`db:assert`** is the runner for 2.7's isolation assertion, 2.8's ledger
  verification and 2.12's lock assertion. Each of those adds one file to
  `scripts/db/sql/`; none of them creates a second runner.
