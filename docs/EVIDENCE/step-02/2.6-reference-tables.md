## 1. What the sub-step adds

the timestamp map in `migrations/README.md`.

| Table               | Holds                                                                             |
| ------------------- | --------------------------------------------------------------------------------- |
| `currencies`        | ISO 4217 codes; USD is the only base currency (display rows allowed)              |
| `timezones`         | IANA zone names with the standard offset, for display                             |
| `countries`         | ISO 3166-1 codes with the calling code used by phone formats                      |
| `tax_jurisdictions` | Jurisdiction code, country, level, display name and date window; rates are step 6 |

It also adds five foreign keys that the earlier sub-steps deferred in writing,
each with its own leading index and `ON DELETE RESTRICT`:

| Table              | Column          | References              |
| ------------------ | --------------- | ----------------------- |
| `companies`        | `country_code`  | `countries (iso_code)`  |
| `company_settings` | `timezone`      | `timezones (iana_name)` |
| `company_settings` | `currency_code` | `currencies (code)`     |
| `plans`            | `currency_code` | `currencies (code)`     |
| `subscriptions`    | `currency_code` | `currencies (code)`     |

Two more keys sit between the new tables: `countries.default_currency_code`
and `tax_jurisdictions.country_code`.

Row level security is not enabled here. The intent to give authenticated
tenants read-only access is recorded in the migration header; 2.7 enables the
policies with `current_company_id()`, as the 2.3 to 2.5 tables are also waiting
for it.

## 2. Design decisions

- **Platform rows only.** Every table carries `company_id` with a named check
  `chk_{table}_company_id_absent` that holds it null.
- **Two indexes per code.** An ISO code is never reused, and a foreign key can
  only point at an unconditional unique index. Each reference code therefore
  has a full unique index (the foreign key target, and it keeps a retired code
  reserved) and a partial unique index on `deleted_at IS NULL` (the soft-delete
  standard, check 17). The pair is named `idx_{table}_{column}` and
  `idx_{table}_{column}_live`.
- **The base currency is USD by a check and by an index.** `chk_currencies_base_is_usd`
  refuses any base row other than USD, and `idx_currencies_is_base_live` allows
  at most one live base row.
- **The timezone is an IANA name, and the offset is for display.** Calculations
  read the zone database at run time. The offset is stored in quarter hours,
  from UTC-12 to UTC+14, so a value that drifts from the standard is refused.
- **Tax jurisdiction windows cannot overlap.** A unique index on `(code,
effective_from)` does not stop a window that starts inside another. The
  trigger `trg_tax_jurisdictions_refuse_overlap` refuses an insert or update
  whose window overlaps a live window for the same code, and takes a per-code
  advisory lock first so two concurrent writers cannot both pass the check.
  Soft-deleted windows are ignored.
- **A jurisdiction code is built from its country.** `starts_with(code,
country_code)` is checked, and a country-level row carries no region while a
  state or local row must name one.
- **Only two rows are seeded by the migration.** USD and UTC are inserted
  because the column defaults of `company_settings` and `plans` name them, and a
  default that points at a missing row would fail on the first insert. Every
  other row is seeded in 2.14.
- **The rollback refuses while a tenant still uses a reference value.** See
  section 5.

## 5. Defects the loop found, and their fixes

Two defects in the first draft were found by the loop, not by reading. Both
are fixed in the committed files.

1. **The rollback could orphan data it could not restore.** The first draft
   dropped the reference tables and their foreign keys even when a company still
   named a country. The re-migrate then failed to re-add `fk_companies_countries`,
   because the country no longer existed in the table it referenced. The down
   file now raises `restrict_violation` (23001) while `companies.country_code`
   or a `company_settings` timezone or currency other than UTC and USD is
   in use. The whole file is one transaction, so the refusal drops nothing.
2. **The up file added the foreign keys before the seed rows existed.** On a
   database that already held a `company_settings` row with the default `UTC`,
   re-adding `fk_company_settings_timezones` validated against an empty
   `timezones` table and failed with 23503. The USD and UTC inserts now run
   before the deferred foreign keys.

Probe mistakes, corrected in the probe and not in the schema:

- an offset of 390 minutes was read as an invalid value; it is a valid
  UTC+06:30 zone. The probe now uses 385, which is not a quarter hour;
- an `INSERT` named six columns and supplied seven values (42601); the column
  list was extended;
- an `UPDATE` that was meant to move a window into a live one matched no row
  only because the insert before it had failed; with the insert fixed the
  update is tested.

## 6. Behaviour on the real constraints

The probe ran 47 assertions on `kd_step26`. Each refusal is matched to its
SQLSTATE, and an unexpected code counts as a failure.

- **Foreign keys refuse unknown codes (23503):** a company country, a settings
  timezone, a settings currency, and a tax jurisdiction country outside the
  table.
- **Restrict stops deletes (23503):** USD while settings and countries use it,
  Bangladesh while a tenant uses it, Asia/Dhaka while settings use it.
- **The base currency is USD only (23514):** a second base currency is refused
  by the check, and a second USD row by the unique index (23505).
- **Codes are formatted and bounded (23514):** lower-case country and
  jurisdiction codes, a two-letter alpha-3, a short numeric code, a calling code
  without a plus or with a leading zero, five minor units, a timezone with a
  trailing space, an offset off the quarter hour, and an offset past UTC+14.
- **A retired code stays reserved (23505):** a soft-deleted display currency
  cannot be re-inserted. A soft-deleted row with no references can be purged.
- **Jurisdiction levels agree with their regions (23514):** a state row without a
  region, and a country row with one.
- **Overlapping windows are refused (23P01):** an overlap, an open-ended window
  starting inside another, an update that moves a window into a live one, and
  an open-ended window that starts before a live one.
- **Adjacent and freed windows are accepted:** a window that starts on the end
  date of another, and a window that re-uses the dates of a soft-deleted row.
- **The deferred indexes exist:** all twelve reference and deferred-key indexes
  named in the verification query are present.

The seeded rows are checked too: USD is the base currency with two minor
units, UTC has offset zero, and re-running the seed insert changes nothing.

  reference table is a read for authenticated tenants and no write.
- **The full ISO lists, the display currency set and the Asian zone list:**
  2.14 seeds. The only rows here are USD and UTC.
- **Rates, the rate history and the tax presets:** step 6 for rates and 2.14 for

  development database with company rows that name a country or zone outside
  the seeds must seed first, as the migration header records.
